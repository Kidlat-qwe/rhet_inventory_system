RHET Inventory System API Keys documentation

How the API Keys page works

Admin guide for generating, regenerating, and revoking integration keys used by external systems (CMS, HR, vendors, and other partners).

What this page is for

The API Keys page manages machine-to-machine credentials for /api/v1/integrations/*. These keys are not for browser logins or Firebase users.

  • Each key belongs to one partner systemCode (derived from the system name).
  • RHET stores a hash only. The full key is shown once after generate/regenerate.
  • Partners send the key as header X-Integration-Key from their backend only.

1. Generate an API key

  1. Open Management → API Keys.
  2. Click Generate API key.
  3. Enter a system name (display name). RHET derives systemCode: letters/numbers uppercased, spaces become _ (example: HR Portal → HR_PORTAL).
  4. Choose expiration: no expiration (typical), 7 days, or 1 month.
  5. Submit, then copy values from the reveal modal immediately.

2. What to copy for the partner

Field Partner env Notes
Integration API URL INVENTORY_API_URL Ends with /api/v1/integrations
API key INVENTORY_INTEGRATION_KEY Shown once. Format rhet_<system>_<secret>
System code Partner reference prefix Used as sourceSystem on stock requests

Suggested partner .env

INVENTORY_API_URL=https://api-inventory.lca-app.com/api/v1/integrations
INVENTORY_INTEGRATION_KEY=rhet_<system>_<secret>
INVENTORY_WEBHOOK_URL=https://partner-api.example.com/api/webhooks/inventory
Never put the integration key in a frontend/mobile app env. Share it over a secure channel (password manager / encrypted message), not long-lived chat screenshots.

3. Connection status on the page

After the partner starts calling the integration API (for example GET /catalog), the client card moves toward Connected based on successful authenticated traffic.

4. Regenerate

  1. Find the system → Regenerate.
  2. Copy the new key to the partner.
  3. Partner updates secrets and redeploys.
  4. The old key stops working immediately.

5. Revoke

  1. Find the system → Revoke.
  2. Hash is cleared; integration calls return 401.
  3. Use when a partner is offboarded or a key must be disabled without issuing a replacement yet.
CMS / PSMS note: CMS is already onboarded. Do not regenerate the live CMS/PSMS key unless you are intentionally rotating it with the CMS team.
